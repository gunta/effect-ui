Add `Html.template` (and `View.template`), for markup that differs in a few values. A template is written once with the helper, reading the values that change from `$`, and returns a function from those values to the element: `Html.template<Msg, { label: string }>((h, $) => h.li(h.a.on("click", $.select).children($.label)))`. The browser host renders it by copying the nodes it built for the first one and writing the slots, and patches it by comparing slots; the server renderer, hydration and test hosts read it as the element the helper would build. The code that copies and patches a template's nodes comes with `Html.template`, so an app that makes no template doesn't ship it; a template made with `View.template` is built as any element on every host. A slot is the whole value of an attribute, a handler, the root's key, or the whole text of a child. A slot that is an element's only child is that element's content: it takes text, or an array of nodes such as `h.list` returns, so a page whose layout doesn't change can be a template with its lists in slots, and a render patches only the lists. The element a template returns keeps the requirements of the nodes in its slots, and a template can be built inside another, with the outer one's slots in its own.

Add `h.list(items, { key, selected }, render)`, which builds a row again only when its item, compared with `===`, or whether it's the selected one changes. It tells the runtime which rows changed, where rows were inserted or removed, or which two traded places, so a render that changes a few rows of a long list patches and moves those only.
